# Android App Changelog

## 1.1.0 — Production milestone

### اتصال و Backend

- اتصال مستقیم ربات با BotFather Token جایگزین UI قدیمی Worker URL + کد ۸ کاراکتری شد.
- Token واقعی با Telegram `getMe` در Backend اعتبارسنجی می‌شود.
- BotFather Token داخل گوشی ذخیره نمی‌شود.
- Bot Token در دیتابیس فقط به‌صورت AES-256-GCM محافظت‌شده نگهداری می‌شود.
- Webhook هر ربات به‌صورت خودکار روی Cloudflare Worker تنظیم می‌شود.
- App Session محدود به Merchant صادر و داخل Android با Keystore محافظت می‌شود.
- Worker Production روی `app-telegram-cc.bustling-larch.workers.dev` فعال شد.
- اتصال Production به Supabase اختصاصی `db_tel_cc` تأیید شد.

### مدیریت فروشگاه

- داشبورد تعداد مشتری، محصول، سفارش و فروش ۳۰ روز اخیر.
- صفحه مدیریت دسته‌بندی‌ها با ساخت، ویرایش، ترتیب نمایش، فعال/غیرفعال و حذف.
- صفحه مدیریت کامل محصولات با نمایش دسته‌بندی هر محصول.
- ساخت محصول با انتخاب دسته‌بندی اختیاری.
- ویرایش نام، قیمت، توضیحات و دسته‌بندی محصول.
- فعال/غیرفعال کردن سریع محصول.
- حذف محصول فقط پس از تأیید کاربر.
- همگام‌سازی دسته‌بندی‌ها هنگام ورود به صفحه محصولات.

### مدیریت مشتری‌ها

- گزینه «مشتری‌ها» در Drawer سمت راست.
- فهرست مشتریان همان فروشگاه با محدودسازی `merchant_id` در Backend.
- جست‌وجوی محلی بر اساس نام، یوزرنیم، شماره تلفن و شناسه تلگرام.
- نمایش شماره تماس، آدرس، شناسه تلگرام، تاریخ عضویت و موجودی کیف‌پول.
- موجودی کیف‌پول فقط Read-only است تا عملیات مالی بدون Ledger انجام نشود.

### مدیریت سفارش‌ها

- فهرست سفارش‌ها با نمایش مشتری، مبلغ نهایی و وضعیت.
- صفحه مستقل جزئیات سفارش.
- نمایش شماره تماس، روش ارسال، آدرس و زمان ثبت سفارش.
- نمایش ریز اقلام سفارش با نام Snapshot محصول، تعداد، قیمت واحد و جمع هر ردیف.
- نمایش جمع محصولات، مبلغ تخفیف و مبلغ نهایی.
- تغییر وضعیت سفارش از داخل صفحه جزئیات.
- تازه‌سازی جزئیات سفارش و همگام‌سازی فهرست سفارش‌ها.
- Back Navigation از جزئیات سفارش به لیست سفارش‌ها.

### امنیت و دیتابیس

- دیتابیس مستقل پروژه: `db_tel_cc`.
- RLS روی جدول‌های public فعال است.
- Queryهای مدیریتی به `merchant_id` Scope می‌شوند.
- Tenant-integrity triggerها از اختلاط داده بین فروشگاه‌ها جلوگیری می‌کنند.
- Supabase Security Advisor در ممیزی نسخه 1.1.0 بدون هشدار امنیتی است.
- Service-role/secret key فقط روی Backend نگهداری می‌شود.

### Release و Update

- `versionCode` از 1 به 2 افزایش یافت.
- `versionName` از 1.0.0 به 1.1.0 افزایش یافت.
- `applicationId` بدون تغییر `ir.asteam.telegramcc` باقی ماند.
- Gradle برای استفاده از Keystore ثابت Production آماده شد.
- Signing credentialها فقط از Environment Variables خوانده می‌شوند.
- Android CI اکنون Debug APK، Release unsigned APK، ZIP سورس و SHA-256 تولید می‌کند.
- Release نهایی با Keystore ثابت پروژه امضا می‌شود تا نسخه‌های بعدی Update-friendly باشند.
