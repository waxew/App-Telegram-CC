# 📄 توضیحات پروژه (Project Overview)

## این پروژه چیست؟

یک **ربات تلگرامی فروشگاه‌ساز** (Telegram Store Builder Bot) است. یعنی خودِ
این پروژه یک فروشگاه نیست؛ بلکه «کارخانه‌ی ساخت فروشگاه» است.

هرکسی که بخواهد یک فروشگاه تلگرامی داشته باشد:

1. یک ربات خالی و جدید در @BotFather می‌سازد و توکنش را می‌گیرد
2. وارد ربات اصلی این پروژه می‌شود و همان توکن را برایش ارسال می‌کند
3. از همان لحظه، ربات خودش (با همان یوزرنیمی که خودش انتخاب کرده) تبدیل به
   یک فروشگاه کامل می‌شود: مشتری‌ها می‌توانند دسته‌بندی و محصولات را ببینند،
   به سبد خرید اضافه کنند و سفارش ثبت کنند؛ و خودِ صاحب فروشگاه از داخل
   همان ربات، یک پنل مدیریت کامل در اختیار دارد (محصولات، سفارشات، کاربران،
   مالی، کدهای تخفیف، تنظیمات و گزارش).

هیچ اپلیکیشن جداگانه‌ای (اندروید/iOS/وب) وجود ندارد — همه‌چیز کاملا داخل
خودِ اپلیکیشن تلگرام و با استفاده از دکمه‌ها و کیبورد‌های خودِ تلگرام اجرا
می‌شود، دقیقا مثل چیزی که در ویدیوی نمونه دیده شد.

## هدف پروژه

هدف، فراهم‌کردن یک زیرساخت **چندمستأجری (Multi-tenant)** است: به‌جای این‌که
برای هر فروشگاه یک نسخه‌ی جداگانه از برنامه نوشته و روی سرور جدا اجرا شود،
یک «موتور» واحد نوشته شده که هم‌زمان به هزاران ربات/فروشگاه مختلف سرویس
می‌دهد. تفاوت هر فروشگاه فقط در «داده»هایش است (محصولات، رنگ متن
خوش‌آمدگویی، کانال اجباری و ...)، نه در کدش.

## زبان برنامه‌نویسی و ابزارها

| بخش | فناوری استفاده‌شده | دلیل انتخاب |
|---|---|---|
| زبان اصلی | **JavaScript** (ES Modules, بدون TypeScript) | خوانایی بالا و یادگیری راحت‌تر برای کسی که تازه دارد کد را می‌خواند |
| فریم‌ورک ربات تلگرام | **[grammY](https://grammy.dev)** | یکی از مدرن‌ترین کتابخانه‌های Bot API تلگرام، با پشتیبانی رسمی از Cloudflare Workers |
| محل اجرا (Hosting) | **Cloudflare Workers** | سرورلس (Serverless)، رایگان تا حجم قابل‌توجهی از ترافیک، و بدون نیاز به مدیریت سرور |
| دیتابیس | **Supabase** (روی Postgres) | دیتابیس رابطه‌ای قدرتمند به‌همراه یک کتابخانه‌ی جاوااسکریپتی ساده برای کوئری‌زدن |
| ارتباط با تلگرام | **Telegram Bot API** (رسمی) | همان API استانداردی که خودِ تلگرام مستند کرده |

### چرا Cloudflare Workers به‌جای یک سرور معمولی؟

چون کاربر گفته بود به Cloudflare و Supabase دسترسی دارد، و این ترکیب برای
یک ربات با تعداد کاربر متغیر (از چند فروشگاه کوچک تا هزاران فروشگاه)
مقیاس‌پذیرتر و کم‌هزینه‌تر از نگه‌داشتن یک سرور همیشه-روشن است: Worker فقط
وقتی پیامی می‌رسد اجرا می‌شود و هزینه‌ای برای زمان بیکاری پرداخت نمی‌شود.

### چرا Supabase به‌عنوان دیتابیس؟

تلگرام هیچ فضایی برای ذخیره‌ی دائمیِ اطلاعاتی مثل لیست محصولات، سفارش‌ها یا
کاربران در اختیار سازنده‌ی ربات نمی‌گذارد؛ فقط پیام رد و بدل می‌کند. پس این
اطلاعات باید جایی، بیرون از تلگرام، ذخیره شوند. Supabase یک Postgres کاملا
مدیریت‌شده (Managed) با API آماده و رایگان برای شروع کار در اختیار می‌گذارد.

## معماری کلی (خلاصه)

```
کاربر در تلگرام
      │
      ▼
Cloudflare Worker  (src/index.js)
      │
      ├─ اگر مسیر /webhook/master بود → src/masterBot.js
      │      (ثبت توکن جدید و ساخت فروشگاه)
      │
      └─ اگر مسیر /webhook/store/<id> بود → src/storeBot/engine.js
             (اجرای منطق مشترک فروشگاه، با داده‌های همان merchant)
                   │
                   ├─ customerHandlers.js   (خرید مشتری)
                   ├─ adminCatalog.js        (محصولات/دسته‌بندی)
                   ├─ adminOrders.js         (سفارشات/گزارش)
                   ├─ adminUsers.js          (کاربران/همکاران)
                   ├─ adminFinance.js        (کارت/تخفیف)
                   └─ adminSettings.js       (تنظیمات عمومی)
                             │
                             ▼
                     Supabase (Postgres)
```

## این پروژه برای چه کسی مناسب است؟

برای کسی که می‌خواهد یک سرویس SaaS بسازد و آن را به مشتری‌های مختلف (که هرکدام
فروشگاه خودشان را می‌خواهند) اجاره بدهد — دقیقا مثل مدل کسب‌وکاری که در
ویدیوی نمونه («Babba.ir») دیده شد.
